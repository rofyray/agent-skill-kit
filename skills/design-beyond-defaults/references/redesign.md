# Redesign and preservation

## Set the change boundary

Infer from the actual request, not the word redesign alone. Record the depth briefly:

- Restyle: update materials, typography, spacing, and presentation while preserving information architecture and behavior. This is the default when the request gives no authority to restructure.
- Restructure: change hierarchy, grouping, navigation, or task flow within the requested scope. Use when the user asks for those changes or an end-to-end redesign that clearly includes them.
- Small refinements belong in Polish. Audit and Critique remain read-only unless changes are requested.

Do not force a commit or stash merely because unrelated changes exist. Inspect the working state and preserve user work. A URL without editable source supports an audit or proposed redesign, not a claim that the deployed application changed.

## Establish the baseline

Confirm that the supplied source is the requested product and route. If a named workflow or defect belongs to a different or missing interface, do not restyle an unrelated available page as a substitute. Ask for the missing target or return a scoped plan; a clearly labelled draft still needs to address the authorized artifact.

Inspect the current interface, repository, tests, and design system. Record only contracts material to the change: facts/prices/legal meaning, content hierarchy, route destinations, fields and validation, permissions, state transitions, data semantics, analytics/test hooks, and accessibility behavior. Distinguish working requirements from pre-existing defects and unknowns.

Capture before views and execute the critical journeys when available. A contract is an outcome, such as "an invalid email cannot submit" or "back navigation restores the filter", not just a DOM selector. A link or handler inventory helps discover omissions but cannot prove behavior. Preserve the baseline; record authorized removals or changed requirements with the actual user decision rather than silently deleting entries.

## Apply the direction

Map materials onto existing semantic tokens and installed framework/library conventions. Add missing roles only where needed. Do not create a parallel global token system or replace a working component library just to match a specimen.

Inspect the representative slice with real content. Continue in coherent component or route batches. Keep shared shell changes under regression checks. Do not rewrite tests to make a regression disappear. A deliberate structural change still preserves requirements unless the user authorized changing those requirements.

Reuse an existing DESIGN.md or equivalent for durable decisions if useful. Keep temporary screenshots, findings, and test records separate. Avoid writing a design record for a trivial visual change, and never create global cross-project taste history by default.

## Compare outcomes

Re-execute baseline journeys against the changed interface, inspect the same relevant views, and check required content. Note what the original did better as well as improvements. Recheck evidence after later code changes. A retained handler name or successful inventory comparison is not a functional pass.

Compare the entire relevant task, not only first impressions: an earlier version may reach the input sooner while a redesign makes the result clearer. Preserve effective visual identity when correcting task access or density. Before attributing a new defect, reproduce it in a settled state and check the baseline; capture artifacts, pre-existing behavior, and authorized changes require different responses. Restyling alone does not authorize replacing working validation semantics merely to obtain a more integrated screenshot.

When a visual critic requests removal of a required control, keep the control and improve its presentation. When reviewers disagree about a defect, reproduce the triggering state or inspect the requirement; do not settle it by majority vote. Unresolved claims remain needs review.

Return the artifact, change boundary, meaningful before/after comparison, preservation results, approved requirement changes, and limitations. Budget exhaustion may leave work incomplete; report the remaining states or journeys rather than relaxing the bar.
