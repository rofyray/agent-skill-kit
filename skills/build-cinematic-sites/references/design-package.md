# Site Design Package

Use this as an adaptable output structure. Omit inapplicable fields rather than filling a small project with empty ceremony. Keep one current package with accepted decisions and explicit changes; implementation and media production should consume the same version.

## 1. Brief and evidence

Record subject, audience, visitor goal, requested pages, selected mode, scope boundary, locked requirements, and acceptance criteria. Separate sourced facts from assumptions. List unresolved decisions only when they affect the work.

## 2. Creative direction

Write a short design thesis anchored in the subject. Define visual composition, palette roles, typography roles and required glyph coverage, imagery, and motion character. Include exact token values once established. Derive these from the actual brand and treatment; do not require a font trio, tinted canvas, or fixed visual style.

Identify a signature element only if it serves the experience. State what stays quiet around it and why it helps the visitor. Identify references by the properties they influence, such as lighting or rhythm, rather than copying their identity or entire layout.

## 3. Pages, content, and copy

List pages and sections in reading order with each section's purpose, content, evidence, action, and responsive treatment. Include navigation, footer, and relevant empty/error states. Mark exact approved strings with stable identifiers so media, page content, and revisions stay synchronized.

| Copy ID | Exact text | Placement | Status/source |
| --- | --- | --- | --- |
| hero-title | User-approved headline or clearly marked draft | Hero heading | Approved or draft |
| primary-action | Exact label | Main action | Destination and behavior |

Do not populate testimonials or claims without evidence. Build approved copy faithfully; update this record when edits are requested or a correction is agreed.

## 4. Asset and production map

| Asset | Role | Origin and identity constraints | Production route | Status |
| --- | --- | --- | --- | --- |
| Hero visual | Introduce the subject and support the first reading moment | Supplied or planned; preserve named details | Existing file, generated plate, controlled graphic, or hybrid | Needed, draft, inspected, accepted |
| Static alternative | Carry the same essential message without motion | Crop and composition selected deliberately | Supplied still or inspected extraction | Status |

For each produced asset record aspect, resolution, intended crop, transparency/audio requirements, asset references, actual tool/settings, budget or attempt authorization, and review status. Keep raw files outside the public asset set. A generated job and an accepted artifact are different states.

## 5. Story and motion map

Choose static, ambient playback, scroll-driven footage, deterministic interaction, or a justified combination. For each beat identify:

| Beat | Visitor message and copy IDs | Entering/exit states | Scroll interval or time | Focus and safe text region | Motion and fallback |
| --- | --- | --- | --- | --- | --- |
| Opening | What becomes clear immediately | Visible initial state and next state | Chosen unit, labeled provisional until tested | Subject location and responsive crop | Optional entrance; readable without it |
| Arrival | What the visitor can do next | Final composition | Reading hold or final section | Heading and action clearance | Stable end state |

Use seconds for linear media and normalized progress or scroll distance for the page. Record the mapping between them. Include seams and direction changes for chained footage. Keep critical information in semantic page content even when the media also illustrates it.

## 6. Responsive and accessible alternatives

Specify narrow, short, wide, coarse-pointer, keyboard, zoomed, reduced-motion, media-failure, and script-failure states as relevant. List which media each mode loads. A static alternative needs its own composition and content order, not an empty tall container with the video removed.

Record accessible names, focus behavior, interaction equivalents, contrast targets by text size, and alternatives to audio or visual-only proof. Include live transitions between motion modes so resizing or preference changes do not leave hidden content.

## 7. Implementation and acceptance

Record the existing stack or selected platform, page/component boundaries, asset locations, preview method, integration dependencies, and performance budgets. Name the actual form destination or mark the demo honestly. Treat unconnected integrations as open work.

Specify evidence required: screenshots at representative sizes, keyboard paths, real interaction states, media failures, live preference changes, and relevant runtime/build checks. Separate desired targets from measured results, and distinguish emulation from physical-device testing.

## 8. Handoff and revision record

Record completed artifacts, local or supported preview location, asset origins, processing settings, reviewed states, outstanding limitations, and concise changes from the last accepted version. Keep only current relevant decisions in the active package. This document should remain useful if a different agent or designer continues the work without the skill installed.
