# Visualize a second brain

Use this mode to create a local, interactive 3D view of an existing source-grounded vault. The bundled viewer uses Three.js and 3d-force-graph, with deterministic anatomical and expanded-region layouts. No network service, API key, Node.js installation, or Obsidian plugin is required to generate or use it. Python 3.10+ and a browser with WebGL 2 enable the complete local path. The searchable list and evidence inspector remain available if 3D graphics are unavailable.

## Generate and open

1. Identify the exact authorized vault. Read its engine and configuration. Inspect its structure rather than assuming an arbitrary notes folder conforms to this skill. If the user requested only a design or explanation, remain read-only.
2. Use the scripts from the current skill installation for existing vaults. Newly initialized vaults also contain both scripts and the viewer under `automation/`. Do not silently replace an older vault's helpers or canonical engine merely to render a view.
3. Run:

   ```bash
   python3 <skill-directory>/scripts/second_brain.py visualize <vault-path> --json
   ```

   The default output is `<vault-path>/.second-brain/visualization/`. `--output <new-directory>` selects a directory outside the vault. Existing output is refreshed only if its ownership marker identifies it as generated by this tool; unrelated directories and symlinks are rejected. Do not remove a lock until confirming no export is active.
4. Read the counts and diagnostics. Broken or ambiguous links are reported and excluded from connections, not guessed. An empty wiki is valid; never seed demo content in a user's vault. Generation is not a semantic lint or a raw-integrity check.
5. When local server execution and a browser are available, run:

   ```bash
   python3 <skill-directory>/scripts/second_brain.py visualize <vault-path> --serve --open
   ```

   The process prints a free loopback URL and remains running until Ctrl+C. Omit `--open` when using the host's browser-opening tool. `--port 8765` chooses a fixed port if needed. Bind only to loopback; the bundled server exposes an allowlist of generated files, not the vault. It does not watch the vault. Running the export command again refreshes the snapshot; the viewer's **Reload snapshot** button then reads it.
6. Test orbit, pan, zoom, search, selection, neighborhood, and evidence details when browser control is available. Inspect reduced-motion and narrow-layout behavior for a new viewer build. Do not claim these checks ran when only file generation was possible.

## What the graph means

| Item | Meaning |
| --- | --- |
| Page node | One Markdown file under `wiki/`, including unindexed pages. |
| Reference edge | An explicit wikilink or relative Markdown link between wiki pages. Duplicate references share one edge with original locators retained. |
| Evidence edge | A page's `sources` metadata points to an existing file under `raw/`. This is recorded provenance, not a fresh verification of its claims. |
| Source node | A raw file's relative path and recorded/unrecorded status. Raw contents are never copied into the snapshot. Hidden initially; enable **Include source files**. |
| Region | First matching second-level index heading, then first tag, then Unfiled. It is an organizational choice, not a biological brain region. |
| Unconnected page | No distinct incoming or outgoing explicit wiki-page neighbor. Evidence and index membership do not inflate this count. |
| Recent activity | Pages whose `updated` metadata falls within the last seven days. This is not a historical replay or live agent telemetry. |

Index headings and page metadata supply the existing organization. The renderer never invents semantic connections, infers support/contradiction from a generic link, or rewrites notes to improve appearance. Code examples and frontmatter are excluded from body-link extraction. Folder and file symlinks are not followed. The resolver supports path-qualified links, display labels, and heading fragments; frontmatter aliases and arbitrary Obsidian plugin syntaxes are not resolved.

The exported schema is version 1: `name`, `nodes`, `links`, `diagnostics`, a content `digest`, and UTC `generatedAt`. Nodes use exact vault-relative paths as IDs. Edges carry `source`, `target`, `kind`, and `locators`. Page summaries, tags, and titles are private knowledge too: the snapshot must not be published or uploaded without a separate request. It contains no absolute vault path, raw contents, or full note bodies.

## Interaction and performance

- **Brain** places pages inside a procedural two-hemisphere outline; **Explore** spreads the same topic groups apart. Positions derive from identity and group, so adding an unrelated page does not move existing nodes. Renaming a page or regrouping it changes its position. These layouts do not run continuous force physics and are not a semantic-distance metric.
- Select a node or keyboard-accessible library result for its summary, status, connected pages, relative path, and evidence locators. **Page details & open original** contains metadata, the relative path, and **Open in Obsidian**. Opening in Obsidian requires the named vault to be registered in Obsidian; use the displayed relative path in another editor otherwise.
- **Show neighborhood** limits the current view to immediate incoming/outgoing references and, when enabled, evidence nodes. **Reset view** clears search, group, status, and neighborhood restrictions.
- Ambient pulses are decorative, distributed across real visible edges. Selected mode highlights the selected page's connections; recent mode uses updated dates. At most 48 connections pulse at once. Motion starts off for reduced-motion users. Glow is optional. Background tabs stop rendering.
- The entire snapshot remains searchable. Above 1,200 matching items, the whole-vault view collapses to region nodes; select a region to expand it. Detailed rendering is capped at 1,200 nodes and 6,000 edges and reports shown/total counts. Filter further to inspect omitted items. The list loads in batches of 60 on desktop and six on phones and is not limited to the rendered subset.
- A static layout does not guarantee idle GPU usage is zero: the viewer continues drawing while visible so camera interaction remains available. Very large snapshots still have CPU/memory costs. Measure representative real vaults before claiming capacity or frame-rate guarantees.

## Handoff without a local runtime

With access to a snapshot of the vault and an execution environment, generate the viewer and offer its complete output directory as a ZIP. Explain that it is a dated snapshot. The recipient can serve only that extracted directory with a local static server, for example `python3 -m http.server 8765 --bind 127.0.0.1 --directory <extracted-viewer>`, and open the loopback URL. Direct `file://` opening is not supported because the page fetches graph.json. Do not promise a server inside an isolated cloud environment is reachable from the user's computer.

Without execution, the skill still supplies the scripts and viewer assets for a precise local handoff; do not claim that a custom graph was generated. Without vault access, request the exact vault or connected snapshot. Do not substitute another visible folder or invent personal knowledge.

Visualization refreshes only disposable artifacts, not `index.md` or `log.md`. Automatic refreshing, query-path illumination, historical replay, semantic suggestions, and database-backed graph storage are separate future capabilities. Do not schedule a watcher or install a service as part of this mode.
